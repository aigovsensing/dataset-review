# 영어 지원 (English support)

홈페이지·이슈 양식·검토 결과가 **한국어 / English** 두 언어를 지원합니다. 한국어가 정본이고, 영어는 그 위에 얹힌 층입니다.

## 1. 사용자 관점

| 하는 일 | 방법 |
| --- | --- |
| 언어 바꾸기 | 홈페이지 **우측 상단 `한국어 \| English`** 버튼. 선택은 브라우저(localStorage)에 저장되고, 작성 중이던 입력값은 보존됩니다. |
| 처음 방문 시 언어 | 주소의 `?lang=en`/`?lang=ko` → 저장값 → 브라우저 언어(한국어면 한국어, 그 밖은 English) 순으로 결정합니다. |
| 영어로 검토 요청 | English 상태에서 **Request review** 를 누르면 **영어 이슈 양식**(`dataset-review-en.yml`, `paper-review-en.yml`)이 열립니다. 제목은 `[Dataset Review] …` / `[Paper Review] …` 입니다. |
| 영어 검토 결과 | 댓글 **위쪽은 영어**, 맨 아래 접힌 `🇰🇷 한국어 원문 (Korean original)` 안에 한국어 원문이 함께 들어갑니다. |

## 2. 동작 방식

### 홈페이지 (`docs/i18n.js` + `docs/i18n-en.js`)
- 원문은 한국어 HTML 입니다. **한국어 모드에서는 번역기가 아무 것도 바꾸지 않습니다.**
- English 모드에서는 화면에 그려진 한국어 텍스트·속성(`placeholder`/`title`/`aria-label`/`alt`)을 사전으로 번역합니다.
  `app.js` 가 나중에 그리는 목록·대시보드도 `MutationObserver` 로 자동 번역합니다.
- 사전 키는 번역 단위의 **태그 골격**(속성 제거·공백 정규화)입니다. 링크 주소 같은 속성은 번역 때 원본 요소에서 같은
  태그 순서로 복사됩니다. 숫자가 섞인 문구는 `rules`(정규식, `$n`=원문 캡처, `%n`=캡처를 사전으로 번역), `[데이터셋검토]`
  같은 접두어는 `sub`(부분 치환)로 처리합니다. JS 가 문자열을 조립하는 곳은 `t("한국어 {값}", {값})` 를 씁니다.
- 번역 전 한국어가 비치지 않도록 English 모드에서는 번역이 끝날 때까지 본문을 잠시 숨깁니다(3초 안전장치).
- 번역하지 않을 곳은 `translate="no"` 를 붙입니다(언어 전환 버튼 등).

### 검토 결과 (`scripts/review_translate.py`)
검토 엔진의 시스템 프롬프트·섹션 번호·판정 어휘('사용 가능' 등)와 대시보드/CSV 집계 파서가 모두 한국어 형식에 묶여 있어,
검토는 **한국어 정본**으로 만든 뒤 영어 요청에만 아래를 수행합니다.

1. 한국어 정본을 **그라운딩 없는 1회 호출**로 영어로 번역합니다(키·모델 순차 폴백).
2. 번역이 **URL·`<details>`·표 행·한글 잔존 비율·길이**를 보존했는지 검증하고, 통과한 첫 결과만 채택합니다.
3. 영어 본문 + 접힌 한국어 원문으로 합성해 게시합니다. 집계 코드는 한국어 원문을 그대로 읽습니다
   (`tests/test_review_translate.py` 가 실제 댓글로 영어 합성본과 한국어 단독본의 파싱 결과가 같음을 검증).
4. 번역이 실패하면 한국어 정본만 게시하고 영어 안내 한 줄을 덧붙입니다(`rerun-review` 로 재시도).

영어 요청 판별: 이슈 본문에 영어 양식의 제목(`### Dataset name` 등)이 있으면 영어입니다. 환경변수 `REVIEW_LANG=en|ko` 로
강제할 수 있습니다. 워크플로의 "검토 시작" 안내 댓글도 같은 규칙으로 영어/한국어를 고릅니다.

## 3. 한계

- 대시보드·CSV 의 **자유 문장**(판단 근거, 소송 요지 등)은 집계 원본(한국어)을 그대로 보여 줍니다. 라벨·표 머리글·판정
  어휘·숫자·날짜 표기는 번역됩니다.
- 상세 가이드 문서(`documents/*.md`)는 한국어입니다. 영어 시작 가이드는 [README.en.md](../README.en.md) 입니다.
- 새 언어를 추가하려면 `docs/i18n-<코드>.js` 사전, `SUPPORTED` 목록, 버튼, 번역 프롬프트의 대상 언어를 확장해야 합니다.

## 4. 화면 문구를 고칠 때

1. `docs/index.html` / `docs/app.js` 의 한국어 문구를 수정·추가합니다.
2. `docs/i18n-en.js` 의 `map` 에 같은 한국어 키(태그 골격)와 영어 번역을 추가합니다.
3. `python -m unittest tests.test_i18n` — 정적 HTML 의 번역 누락·태그 불일치·한글 잔존을 잡습니다.
4. 대시보드처럼 동적으로 그려지는 화면은 `tools/i18n_sweep.js` 로 영어 모드를 훑어 남은 한글을 확인합니다.
   (사용법은 파일 머리말 참고. 데이터에서 온 자유 문장은 남아 있는 것이 정상입니다.)
